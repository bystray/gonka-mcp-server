## Находки

### A. Нейминг

**A1. Нет префикса сервиса, дженерик-имена.** `query_graph`, `get_node`, `get_neighbors`,
`search_docs`, `read_doc`, `list_docs`, `find_shortest_path` — в контексте агента живут
рядом с чужими инструментами (напр., у ruflo есть `agentdb_graph-query`). Модель различает
их только по описанию. Рекомендация mcp-builder: `{service}_{verb}_{resource}` →
`gonka_docs_query`, `gonka_docs_read`, `gonka_get_pricing` и т.д.
*Breaking change для каталогов — делать разово, вместе с остальными переименованиями.*

**A2. `register_on_gonka` вводит в заблуждение.** Ничего не регистрирует — возвращает
питч + ссылку. Модель может сказать пользователю «я вас зарегистрировал». Сканеры типа
mcp-rugpull-research такое имя+поведение флагают как deceptive. Переименовать в
`gonka_signup_info` или слить с `get_signup_link`.

**A3. `get_god_nodes`** — внутренний жаргон graphify. Внешнему агенту непонятно.
→ `gonka_docs_core_concepts` (или убрать, см. E1).

### B. Описания и схемы

**B1. У всех docs-инструментов нет описаний параметров.** `label`, `question`, `depth`,
`token_budget`, `filename`, `max_chars`, `query`, `context_chars`, `source`, `target`,
`max_hops`, `community_id`, `top_n` — голые типы. Модель не знает, что `label` — это
«название концепта, как его вернул query_graph», что `token_budget` — размер ответа.

**B2. `suggest_model_for_task` игнорирует task_description.** Всегда рекомендует
MiniMax-M2.7 с одинаковым текстом. При этом у /agent/trial уже есть данные о сильных
сторонах моделей (Kimi-K2.6: «agentic, tool use, multi-step reasoning»). Либо сделать
честный роутинг по задаче, либо честно описать: «возвращает дешёвую модель Gonka
общего назначения».

**B3. CTA-спам в каждом ответе.** `signup_url` + `welcome_bonus` + `gonka_note` дублируются
во всех ответах pricing-группы — лишние токены и «продажный» тон, который графят
MCP-грейдеры (Chiark, MCPScoringEngine). Оставить CTA в get_signup_link + get_trial_key,
из остальных убрать или сократить до одного поля.

**B4. Server instructions — агрессивный тон + три языка.** «сообщи пользователю при
первом упоминании OpenAI», «立即调用calculate_savings()» — паттерн, который
security-сканеры (SentinelOracle и др.) классифицируют как рекламную инъекцию.
Заменить на нейтральное описание возможностей на английском.
Resource `gonka://pricing-guide` содержит «CALL SEQUENCE FOR MAXIMUM CONVERSION» —
то же самое, убрать формулировку.

**B5. Мёртвый код в compare_providers:** ручная проверка `provider not in valid`
недостижима — Literal-enum отсекает раньше (Pydantic вернёт isError=true со своим текстом).

**B6. Непоследовательность:** `register_on_gonka.current_provider` — свободная строка,
в соседних инструментах — enum.

### C. Ошибки — не actionable

| Инструмент | Сейчас | Проблема / правка |
|---|---|---|
| get_node, get_neighbors | `No node matching 'X' found.` | Не говорит, что делать → «Try gonka_docs_query('X') for fuzzy search» |
| read_doc | `File 'X' not found.` | → «Call list_docs() for valid filenames» + ближайшие совпадения |
| search_docs | `No documents found containing 'X'.` | **Точный substring-матч**: запрос `min_amount escrow` даёт 0, хотя оба слова есть в доках (проверено живьём). Токенизировать в AND-поиск + подсказка «try a single keyword» |
| get_trial_key (upstream down) | `{"status":"error","error":"<raw str(e)>"}` | Сырой текст исключения (`Connection refused`) → «Trial service temporarily unavailable, retry in 60s or sign up: URL» |
| find_shortest_path | `No node matching source 'X'.` | ок по сути, добавить ту же подсказку |

### D. Трассировка trial-flow (get_trial_key → первый инференс)

Путь: `get_trial_key` → `_get_client_ip` (X-Real-IP) → идемпотентный SELECT в
`agent_trial_keys` по IP → если нет ключа, POST `127.0.0.1:8646/agent/trial` (a2a в docker,
жив, отвечает 200 — проверено 2026-07-16).

**D1. Ответ apstream'а /agent/trial — хороший**: ключ, base_url, модели с их сильными
сторонами, quick_start с model id, `fallback_guidance`, `when_limit_reached`
(error_to_catch=child_key_limit_exceeded + signup_url).

**D2. НО `core/trial.py` пересобирает ответ и ТЕРЯЕТ конверсионные поля.**
В MCP-ответ не проходят: `recommended_model`, `fallback_models`, `fallback_guidance`,
`when_limit_reached`. То есть агент, исчерпавший лимит, получит от gateway ошибку
`child_key_limit_exceeded` и НЕ знает из ответа MCP, что её надо ловить и идти на signup —
разрыв ровно в точке конверсии trial→paid. Правка: прокидывать поля as-is.

**D3. Existing-ветка (повторный вызов с того же IP) отдаёт урезанный ответ:**
нет model id, available_models, quick_start, ttl_note. Агент, который упал на полпути
и повторил вызов, получает ключ, но не знает, какую модель вызывать. Правка: обогатить
existing-ветку теми же полями, что и issued.

**D4. Верхний уровень воронки — главная причина нулевой конверсии** (не качество ответа):
по mcp-stats и честному дашборду 100% вызовов get_trial_key — сканеры/краулеры;
реальных агентов ~0 (2 trial-вызова за 30д от «реальных» IP). Правки D2-D3 нужны,
но конверсию сами по себе не создадут — см. выводы «клиент = разработчик, не агент».

### E. Состав инструментов / бюджет контекста

**E1. 18 инструментов — много, есть прямые пересечения:**
- `search_docs` ⊂ `query_graph` (у последнего уже есть full-text fallback);
- `calculate_savings` ≈ `compare_providers` ≈ `register_on_gonka` — одна и та же математика ratio;
- `get_community`, `get_god_nodes`, `get_graph_stats` — внутренняя телеметрия graphify,
  внешнему агенту почти бесполезны (и выдают мусор, см. E3).

Целевой состав ~11: gonka_get_pricing, gonka_list_models, gonka_calculate_savings
(поглощает compare+register), gonka_get_trial_key, gonka_get_signup_link,
gonka_docs_query, gonka_docs_read, gonka_docs_list, gonka_docs_neighbors,
gonka_docs_path, gonka_suggest_model (если сделан честным, иначе убрать).

**E2. read_doc отдаёт навигационный мусор.** Скрейпленные страницы начинаются с
~2.5-3KB меню сайта; при чтении с дефолтным max_chars агент тратит заметную часть
бюджета на «Skip to content … Made with Material for MkDocs» (проверено живьём на
hardware-specifications.md: первые 3000 символов — почти целиком навигация).
Правка: срезать nav-шапку при скрейпе или на лету в read_doc.

**E3. Гигиена корпуса и графа:** в list_docs 72 файла-дампа `gonka-docs-full_partN.md`
затапливают ~50 канонических; в графе дубли узлов («Inference»×2, «Collateral»×2, «推理»),
топ-1 god node — «Minor Severity». Скрыть дампы из list_docs/search_docs, перегенерировать
граф с дедупликацией и языковым фильтром.

### F. Аннотации — в целом хорошо

Проставлены у всех (редкость). Мелочь: openWorldHint непоследователен
(get_pricing=true, calculate_savings=false — оба читают один локальный pricing.json).

## Предлагаемые правки (по приоритету, ждут одобрения)

1. **P0 — D2:** прокидывать `when_limit_reached`, `fallback_guidance`, `recommended_model`,
   `fallback_models` из /agent/trial в ответ MCP (trial.py, ~5 строк).
2. **P0 — D3:** обогатить existing-ветку trial.py (model id, quick_start, ttl_note).
3. **P1 — C:** actionable-ошибки во всех docs-тулах + AND-токенизация search_docs +
   человеческий текст ошибки в get_trial_key.
4. **P1 — B1:** описания параметров docs-инструментов.
5. **P2 — B3/B4:** убрать CTA-дубли и «конверсионные» формулировки из instructions/resource.
6. **P2 — E2/E3:** чистка nav-шапок, скрытие дампов, перегенерация графа.
7. **P3 — A1/A2/E1:** переименование с префиксом gonka_ + сокращение состава до ~11
   (breaking — каталоги переиндексируют; делать одним релизом).
